## Useful gotchas / established conventions for next session
- **Stacked fraction markup** (already used elsewhere in the bank, now used consistently): `<span style="display:inline-flex;flex-direction:column;align-items:center;vertical-align:middle;line-height:1.15;margin:0 0.12em;font-size:0.95em;"><span style="border-bottom:1px solid currentColor;padding:0 0.25em;">NUM</span><span style="padding:0 0.25em;">DEN</span></span>`. Don't write plain `a/b` in new question text.
- **`&minus;` vs plain hyphen**: the bank stores minus signs as the HTML entity `&minus;`, not `-`. A duplicate-check substring containing a minus sign must account for both, or better, pick a distinctive substring that doesn't cross one.
- **Exact substring duplicate check, every time**: `python3 -c "d1=open('portal/practice-tests.js',encoding='utf-8').read(); d2=open('portal/banks.js',encoding='utf-8').read(); print(d1.count('<phrase>'), d2.count('<phrase>'))"` — both must be 0 before splicing a new question. The `find_math_candidates.py`-style `[free]`/`[USED]` fuzzy tags are NOT reliable alone (confirmed by multiple false negatives this session).
- **Domain/skill casing must match exactly** whatever's already in the specific test/slot being replaced — grep a nearby existing entry rather than guessing capitalization.
- **PDF transcription**: always render the page to an image (`pdftoppm -png -r 200`) and read it visually — raw `pdftotext` frequently drops or garbles numbers, math symbols, and occasionally has corrupted/mismatched rationale text in the source PDF itself (found and fixed once this session).
- **Delegating large mechanical batches to background subagents works well** for this codebase — each agent gets its own context for image reads/scratch work, reports back only a summary, keeping the main thread lean. Worth doing again for the two "known remaining work" items above if they're picked up (especially #2, the missing-figures work, which is highly parallelizable per-test).
- **Testing UI interactions locally**: the portal needs a real student login (backend auth) to reach exam/review screens, which this session can't do without live credentials. Instead, extract the relevant `<script>` block + CSS from `index.html` via Python regex into a standalone test HTML page with a fake `window.fetchPortalProgress`/data stub, serve locally, and drive with the browser tool. **Caveat**: the browser tool's own `computer{action:"left_click"}` / `screenshot` actions can introduce a stray interaction that closes an open dropdown/menu between calls — this is a testing-harness artifact, not a real bug. When verifying dropdown/menu state, confirm with `MouseEvent` dispatch (`mousedown`→`mouseup`→`click`) inside a single `javascript_exec` call instead of trusting a `computer` click followed by a separate `screenshot` call.
- **Git housekeeping**: if a multi-commit `git revert <a> <b>` partially fails partway through, running a fresh separate `git revert <b>` afterward achieves the right end state but leaves `.git/sequencer` in a stale "revert in progress" state (no `REVERT_HEAD`, but `git status` reports it). Clean up with `git revert --quit` (safe — doesn't touch commits/files) once you've confirmed the working tree is already clean and the desired commits exist.
